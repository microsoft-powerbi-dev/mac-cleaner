# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MacCleaner: a native SwiftUI macOS app (macOS 14+, arm64 only, Xcode 16+) with four features — Junk Cleaner, Uninstaller, Disk Analyzer, System Monitor (main window + menu-bar extra). No telemetry, no third-party dependencies, and no network access except the opt-in AI providers chosen in Settings › AI (off by default; on-device is the default). App Sandbox is deliberately **off** (it must read `~/Library` and `/Applications`).

## Build & test

The Xcode project is generated by XcodeGen from `project.yml` (repo root) and is gitignored, as are `MacCleaner/App/Info.plist` and `MacCleaner.entitlements`. Edit `project.yml`, never the generated files. Re-run `xcodegen` after adding/removing source files.

```bash
brew install xcodegen
xcodegen                                   # generates MacCleaner.xcodeproj
xcodebuild -project MacCleaner.xcodeproj -scheme MacCleaner build
xcodebuild -project MacCleaner.xcodeproj -scheme MacCleaner test
# single test class / method:
xcodebuild -project MacCleaner.xcodeproj -scheme MacCleaner test -only-testing:MacCleanerTests/SafetyGuardTests
xcodebuild -project MacCleaner.xcodeproj -scheme MacCleaner test -only-testing:MacCleanerTests/SafetyGuardTests/<testMethod>
```

Builds are ad-hoc signed (`CODE_SIGN_IDENTITY: "-"`). Many scan targets need Full Disk Access; after a rebuild macOS may drop the grant (remove and re-add the app in System Settings → Privacy & Security → Full Disk Access).

## Architecture

Feature folders (`Cleaner/`, `Uninstaller/`, `Analyzer/`, `Monitor/`) each pair a pure scanning type with a view file. The view file also holds the feature's `@MainActor @Observable final class …Model`; heavy file-system work is pushed off the main actor via `Task.detached` / task groups and the results are `Sendable` value types.

**Deletion pipeline — the central safety invariant.** All removal (including the original after a move) goes through `Core/Trasher.remove(_:mode:)`, which calls `SafetyGuard.validate(_:)` on every URL before touching it. Never call `FileManager.removeItem`/`trashItem` directly from feature code.
- `SafetyGuard.standard` allows only paths strictly *inside* `$HOME` or `/Applications`; blocks protected subtrees (`/System`, `/Library`, iCloud/CloudStorage, Keychains, Mail, Messages, Photos library, …) and protected exact folders (the roots themselves like `~/Library/Caches` — you may delete their children, not the folder). Comparisons are lowercase/case-insensitive. `validate` additionally rejects symlinks in the parent chain and the app's own bundle. `checkPolicy` is the pure-string half used by tests.
- `SafetyGuard` normalizes paths purely lexically (`SafetyGuard.lexical`); don't reintroduce `NSString.standardizingPath`, whose `/private` stripping depends on whether the path exists. `validate` returns the checked URL and `Trasher` deletes that URL.
- Default mode is move-to-Trash. `.permanent` is reserved for the "Empty Trash" category only (enforced by `CleanupCatalogTests.testOnlyTrashIsPermanent`).

**Junk Cleaner.** `CleanupCatalog.all` is the data-driven list of `CleanupCategory`s. Each `Target` has `contentsOnly` (scan children vs. the folder itself), `excluding` (child names handled by another category, or `CleanupCatalog.protectedCaches` which hold iCloud/Apple ID/download state), and `keepChildFolders` (used for `~/Library/Caches` and `~/Library/Logs`: empty each app's folder but never remove the folder itself — removing `Logs/DiagnosticReports` breaks crash reporting). Items carry an `owner` (the child folder name); `CleanerModel` unchecks items whose owner is a running app's bundle ID. Modes: `.trash`, `.permanent`, `.listOnly` (size shown, not cleanable). `CleanerScanner` scans categories concurrently and preserves catalog order. To add a category, add an entry to `CleanupCatalog.all`; `CleanupCatalogTests` verifies unique IDs and that every cleanable target passes `SafetyGuard` — if it fails, fix the target rather than loosening the guard.

**Uninstaller.** `AppInventory` lists apps; `LeftoverFinder` scans fixed `~/Library` subfolders. Only `.bundleID` matches (exact ID, ID + `.plist`/`.savedState`/`.binarycookies`, or `TEAMID.` + ID) start checked; `.related` (longer IDs like `com.foo.app.beta` — may be another edition), `.sharedGroup` (Group Containers) and `.appName` start unchecked. Files matching another installed app's more specific bundle ID are skipped, and nothing is offered if another copy with the same ID is installed. `com.apple.*` bundles are never matched. `libraryRoot` is injectable for tests.

**Disk Analyzer.** `DiskScanner` builds a size tree with a `CancelFlag` for cancellation, plus `files` (every file ≥ 1 MB, capped at 50k, each with a `FileKind`) and per-kind / per-`AgeBucket` totals over all files; `largeFiles`/`oldFiles` are computed from `files`. `FileKind` classifies by extension (cached per scan) and inherits a folder context (`directoryContext`: `.app`, `node_modules`, `Caches`…) for everything inside. `DiskInsights.spaceHogs` lists folders holding ≥ 1 GB not accounted for by a big sub-folder; `FileFilter` drives the Largest tab. `DuplicateFinder` groups by size → head/tail hash → full SHA-256 (`Core/FileHasher`), skipping hard links; extra copies go through `Trasher`, and one copy per group is always kept. `UsageHistoryStore` saves `UsageSnapshot`s to `~/Library/Application Support/MacCleaner/usage-history.json` after each scan and once per day at launch (capped at 365). Each tab has its own view file; `AnalyzerModel` stays in `AnalyzerView.swift`.

**Advisor (AI).** `DiskAdvisor` always computes `RuleBasedAdvisor` advice first, then (macOS 26+, `#if canImport(FoundationModels)`) asks `FoundationModelsAdvisor` with the rule result as a hint. The final safety rating is `max(model, rules)`, and anything `SafetyGuard.checkPolicy` rejects is `.keep`. Whole-scan reports keep rule-based findings; the model only writes the headline and tips. The provider comes from `AISettings` (UserDefaults; API keys in the Keychain via `Core/KeychainStore`): on-device by default, or a remote provider through `Analyzer/AI/RemoteLLMClient` — Azure OpenAI (`/openai/deployments/{deployment}/chat/completions?api-version=`, `api-key` header), OpenAI, Gemini (OpenAI-compatible endpoint), Ollama and custom OpenAI-compatible servers all use Chat Completions; Anthropic uses `/v1/messages`. `RemoteAdvisor` asks for JSON and decodes leniently. Any failure or missing setup falls back to the rules with a `notice`. Only metadata (path, size, dates, kind) is ever sent, never file contents. `DiskAdvisor.advise/summarize` take an injectable `LLMCompleting` for tests. `NSAllowsLocalNetworking` in `project.yml` permits http to local Ollama/LM Studio.

**Mover.** `Core/Mover` moves items to iCloud Drive / external / network volumes (`StorageDestinations`): `SafetyGuard.validate` the source, check the destination (exists, writable, not inside the source, free space), copy to a unique name, verify (logical size + file count, SHA-256 for files ≤ 2 GB), then remove the original via `Trasher` (Trash by default). On failure the copy is deleted and the original untouched.

**Monitor.** `SystemStats` reads CPU/memory/disk/battery/thermal via Mach (`host_statistics`) and IOKit. `SystemMonitor.shared` is a singleton started in `MacCleanerApp.init`, refreshed by a 2s timer, and shared between the main window and `MenuBarExtra`.

**Settings.** `Shared/Preferences.swift` (`Prefs`) holds every UserDefaults key with its default; `Prefs.register()` runs in `MacCleanerApp.init`. Views bind with `@AppStorage(Prefs.key)`, model code reads `Prefs.*` accessors, and models re-read them in `onAppear` (`reloadPreferences()`). The same `SettingsTabs` (General · Disk Analyzer · Uninstaller · AI) is shown as a sidebar page (`SettingsPage`) and in the ⌘, `Settings` scene. Don't bind `MenuBarExtra(isInserted:)` to `@AppStorage` at the App level — SwiftUI re-evaluates the scene graph endlessly and the app (and the test host) hangs at launch; it uses the `MenuBarSetting` observable instead. Uninstaller sorting (`AppSort`, `AppInventory.sorted`) uses Spotlight's `kMDItemLastUsedDate` / `kMDItemDateAdded`; apps without a date sort last in both directions.

`Core/FileSizer` computes on-disk sizes; `Core/Permissions` detects Full Disk Access heuristically by probing TCC-protected folders; `Shared/Formatting` (`Format`) holds number/byte formatters.
